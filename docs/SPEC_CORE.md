# SPEC_CORE — домен: модели, порты, узлы, реестр блоков

> Обязательная спецификация. Отвечает на вопросы: какие данные есть в системе, что такое узел, порт, параметр, виджет, и что делает каждый из 21 блоков при вычислении.

## 1. Модель `Project`

```python
@dataclass
class Project:
    id: str             # "a1b2c3d4e5f6..." (uuid4.hex, 32 символа)
    name: str           # название, обязательное
    idea_summary: str   # краткая идея, ≤280 символов
    description: str    # подробное описание, без лимита
    schema: SchemaGraph
    created_at: str     # ISO 8601 UTC, напр. "2026-10-26T12:34:56"
    updated_at: str     # ISO 8601 UTC, обновляется при каждом сохранении
```

| Поле | Пояснение |
|---|---|
| `id` | Генерируется при создании (`uuid4().hex`), никогда не меняется. Не «номер по порядку»: uuid безопасен при копировании и слиянии баз |
| `name` | Показывается в сайдбаре и в заголовке окна. Пустым не бывает — сервис заменит '' на «Без названия» |
| `idea_summary` | Поле «Краткая идея». Ограничение 280 символов мягкое: UI не мешает печатать, но счётчик становится DANGER при >280, а `project_service` обрезает до 280 при сохранении |
| `description` | Поле «Подробное описание». Без Markdown-парсера — хранится и показывается как plain text |
| `created_at` | Ставится один раз при создании. Хранится строкой, не объектом — так его легко положить в JSON без мучений |
| `updated_at` | Каждое автосохранение обновляет это поле — видно «когда правил последний раз» |

## 2. Модель `Node` и `Edge`, `SchemaGraph`

```python
@dataclass
class Node:
    id: str        # uuid4.hex
    type: str      # ключ реестра, напр. "parse_html"
    title: str     # заголовок в узле; при создании = spec.title, потом пользовательский
    x: float       # координата левого-верхнего угла на сцене (то, что просит setPos)
    y: float
    params: dict   # {имя_параметра: значение}; состав и типы -> NodeSpec.params

@dataclass
class Edge:
    id: str             # uuid4.hex
    from_node: str      # id узла-источника
    from_port: int      # индекс выхода (0-based) в списке выходов спецификации
    to_node: str        # id узла-приёмника
    to_port: int        # индекс входа (0-based)

@dataclass
class SchemaGraph:
    nodes: list[Node]
    edges: list[Edge]
```

**Пояснения:**

- Индексы портов вместо имён в `Edge`: порядок портов фиксируется спецификацией, поэтому `from_port=0` всегда одно и то же; имена рисуем из спецификации. Переименование порта не ломает сохранённые схемы.
- `x, y` — координаты угла узла (не центра): прямой перенос в `QGraphicsItem.setPos()`, меньше преобразований.
- Порядок в списках не значим; для поиска по id сервисы держат временный индекс `{id: Node}` (не хранится в модели).

## 3. Модель `NodeRuntime`

```python
@dataclass
class NodeRuntime:
    outputs: dict[str, Any] | None   # {"имя_порта": значение} или None (не считался)
    error: str | None                # текст ошибки; None = нет ошибки
    dirty: bool = True               # True = данные устарели, нужен пересчёт
    display_value: Any | None = None # для дисплей-узлов (result): значение входа
```

- Живёт **не в документе**, а в `flow_service` (в таблице `runtime` по node_id).
- При загрузке проекта заполняется repr-строками из JSON (`outputs` с префиксами «восстановлено», см. SPEC_FLOW, п. 10).
- Гарантия: если `error is None`, то `outputs` содержит значение **каждого** выходного порта спецификации (или `None`).

## 4. Типы портов и приведения

```python
PortType = Literal["any", "number", "text", "list", "matrix"]

@dataclass
class PortSpec:
    name: str                     # "a", "b", "out", "yes", "no", ...
    type: PortType = "any"
```

| Тип | Что содержит | Кого принимает | Приведение на входе |
|---|---|---|---|
| `any` | что угодно | всё без изменений | не приводится |
| `number` | `int \| float` | всё | `bool` → `int`; `str` → `float` (точка-разделитель; запятая → точка; ошибка → ошибка приведения); `list` длины 1 → элемент; иначе — ошибка приведения |
| `text` | `str` | всё | `str(v)`; `bool/list/dict` — строковым отображением; `None` остаётся `None` |
| `list` | `list` | всё | `list` — как есть; прочее (кроме None) → `[значение]` (одиночный элемент в списке) |
| `matrix` | `list[list[float]]` (или numpy-массив, если установлен) | `matrix`, `list` | вложенные списки чисел — как есть; плоский список чисел → одна строка `[[...]]`; прочее — ошибка приведения |

Правила:

- Приведение делает движок до вызова `fn`: узел получает уже готовые значения и не преобразует сам.
- Ошибка приведения — это ошибка узла-приёмника (`NodeRuntime.error = "вход a: не число"`), а не источника. Приёмник получает `None`, помечается сломанным, вниз идёт ошибка.
- `None` проходит без ошибок: узел с пустым входом просто отдаёт `None` (или своё «вычислил без входа»).

## 5. Параметры и виджеты (`ParamSpec`)

```python
@dataclass
class ParamSpec:
    key: str                    # имя в Node.params
    label: str                  # подпись в панели параметров
    widget: str                 # "spin" | "line" | "text" | "combo" | "code"
    default: Any                # значение при создании узла
    inline: bool = False        # рендерить виджет в теле узла?
    options: list = None        # для combo
    min: float = 0; max: float = 100; step: float = 1   # для spin
    placeholder: str = ""       # подсказка в пустом поле
    rows: int = 2               # для "text"/"code": высота в строках
```

| Виджет | Qt-класс | Тип значения | Где рендерится |
|---|---|---|---|
| `spin` | QDoubleSpinBox | float | inline (тело узла) и панель |
| `line` | QLineEdit | str | inline и панель |
| `text` | QPlainTextEdit | str | inline (rows) и панель |
| `combo` | QComboBox | str из options | inline и панель |
| `code` | QPlainTextEdit, Consolas | str (выражение) | inline (rows, default 2) и панель |

Правила:

- **inline=True обязателен** там, где параметр — главный смысл узла (число, оператор, выражение, индекс...): редактирование без открытия панели — так работает референс (spin у узла, combo у «**», code у eval).
- Изменение inline-виджета → `project_service.set_param` → live пересчёт (debounce 200 мс). Изменение в панели — то же.
- Панель параметров **всегда** показывает все параметры узла, включая inline.
- У проектных блоков inline=True запрещён (их смысл — читать в панели и в чипе).

## 6. `NodeSpec` — описание блока

```python
@dataclass
class NodeSpec:
    type: str                       # ключ реестра
    title: str                      # название по умолчанию (title узла)
    category: str                   # группа в палитре
    inputs: list[PortSpec]
    outputs: list[PortSpec]
    params: dict[str, ParamSpec]    # по key
    runnable: bool                  # исполняемый или проектный
    fn: Callable | None             # (inputs, params) -> {"порт": значение}
    body_port: str | None           # какой порт показывать чипом; None = нет чипа
    opt_deps: list[str]             # напр. ["numpy"] — опциональные зависимости
```

Контракт `fn` (жёстко):

1. Чистая функция: без Qt, без обращения к файлам/сети/глобальным переменным.
2. Сигнатура: `fn(inputs: dict[str, Any], params: dict[str, Any]) -> dict[str, Any]`.
3. Возвращает словарь, содержащий **каждый** выходной порт своего имени (можно `None`).
4. Входы: уже приведены к типам портов; нет связи → `None`.
5. Параметры: приходят как есть из `Node.params` (значения виджетов уже правильные типы: spin — float, line — str, combo — str, code/text — str).
6. Ошибка делается `raise FlowError("человекочитаемый текст на русском")` — движок отобразит в узле и вниз по цепочке.
7. Типичное время `fn` — миллисекунды; сетевые/файловые операции в v1 запрещены (у блоков нет runnable-действий с IO).

## 7. Реестр исполняемых блоков (v1)

Категория палитры у всех: **«Данные и код»** (точка `ACCENT`). Порядок в палитре — как в таблице.

### 7.1 `number` — Число
- Порты: `[] → [out:number]`. Параметры: `value` (spin, inline, default 2).
- `fn`: `{"out": params["value"]}`.
- Зачем: источник константы (на скрине — узел с spin «2» у оператора «**»).

### 7.2 `text` — Текст
- Порты: `[] → [out:text]`. Параметры: `value` (line, inline, default '').
- `fn`: `{"out": params["value"]}`.

### 7.3 `list` — Список
- Порты: `[] → [out:list]`. Параметры: `items` (line, inline, placeholder «1, два, 3.5»).
- `fn`: разобрать строку по запятым, отрезать края, каждый элемент → число, если парсится, иначе строка; вернуть `{"out": список}`.


### 7.4 `math` — Оператор
- Порты: `[a:number, b:number] → [out:number]`. Параметры: `op` (combo, inline, options `["+", "-", "*", "/", "**"]`, default "**").
- `fn`:

```python
if a is None or b is None:
    return {"out": None}
if op == "+":   out = a + b
elif op == "-": out = a - b
elif op == "*": out = a * b
elif op == "/":
    if b == 0: raise FlowError("деление на ноль")
    out = a / b
elif op == "**": out = a ** b
```

- Это узлы «**» со входом «2» и «+» со скрина; входное значение `6.0` показывается рядом с портом (SPEC_UI, п. 5.5).

### 7.5 `eval` — Python-выражение
- Порты: `[in0:any, in1:any] → [out:any]`. Параметры: `expr` (code, inline, placeholder `in0[0][0]`).
- `fn`: исполнение в песочнице (детально SPEC_FLOW, п. 9): namespaces `{"in0": ..., "in1": ...}`, whitelist builtins; SyntaxError → `FlowError("синтаксис: ...")`; общий протокол ошибок.
- Зачем: «карманный» узел любой логики — прямо как на скрине (`inp[0][0]`).

### 7.6 `get_index` — Элемент [i]
- Порты: `[src:any, i:number] → [out:any]`. Параметры: `i` (spin, inline, default 0).
- `fn`: индексирование `src[i]`: у списка/строки/кортежа — числовой индекс, у dict — ключ `int(i)`; IndexError/KeyError/TypeError → `FlowError("нет элемента [i]")`.
- Чип показывает извлечённый элемент.

### 7.7 `branch` — Ветка
- Порты: `[in:any] → [yes:any, no:any]` (подписи «да»/«нет» при выходах). Параметры: `cond` (combo, inline: «содержит», «больше чем», «равно»), `value` (line, inline).
- `fn`: сравнение значения входа и value; «содержит» / «равно» — строковое сравнение `str(in)`, «больше чем» — числовое (`float` по правилам number-приведения; не удалось → `FlowError("сравнение: не число")`).
- Результат: истина → `{"yes": in, "no": None}`, ложь → `{"yes": None, "no": in}`. Значение «проходит» через активную ветку — так условия строятся без строгой типизации.

### 7.8 `merge` — Объединить
- Порты: `[a:any, b:any] → [out:text]`. Параметры: `sep` (line, inline, default " ").
- `fn`: `str(a) + sep + str(b)`, `None`-части пропускаются (обе None → пустая строка).

### 7.9 `matrix` — Матрица
- Порты: `[] → [out:matrix]`. Параметры: `rows` (text, inline, rows=3, placeholder «1 2 3; 4 5 6»; строки через «;», значения через пробел/запятую).
- `fn`: парс в `list[list[float]]`; если установлен numpy — `np.array(...)` (зачем: дальше работают матричные узлы). Ошибка парса → `FlowError("матрица: строки через ';', числа через пробел")`.

### 7.10 `determinant` — Определитель (numpy)
- Порты: `[m:matrix] → [out:number]`, `opt_deps=["numpy"]`.
- `fn`: нет numpy → `FlowError("установи numpy: pip install numpy")`; иначе `float(np.linalg.det(m))`.
- Это узел `Determinant → 6.0` со скрина.

### 7.11 `inverse` — Обратная матрица (numpy)
- Порты: `[m:matrix] → [out:matrix]`, `opt_deps=["numpy"]`.
- `fn`: как выше, `np.linalg.inv(m)`. Узел `Inverse` со скрина (выход — набор строк-чипов).

### 7.12 `result` — Результат
- Порты: `[in:any] → []`. `fn` отсутствует (нечего вычислять); но чип = значение входа: движок для узлов без выходов просто проверяет вход и передаёт его значение в runtime (см. SPEC_FLOW, п. 6, шаг «дисплей-узлы»).
- Внешность: значение в прямоугольнике-чеке (SPEC_UI, п. 5.5). Это узлы `result` со скрина.

## 8. Реестр проектных блоков (runnable=False)

При вычислении движок вызывает для них стандартную заглушку `fn`: выход = строка `"<title>: <краткое описание параметров>"` (пометка «проектное»; рисуется приглушённым цветом — SPEC_UI). Так проектный блок встраивается в живую цепочку без разрыва.

| Тип | Название | Категория | Входы | Выходы | Параметры |
|---|---|---|---|---|---|
| `site_url` | Сайт / URL | Источники | — | out:any | `url` (line, «https://...») |
| `manual_text` | Текст вручную | Источники | — | out:any | `text` (text, rows=3) |
| `file` | Файл | Источники | — | out:any | `path` (line), `fmt` (combo: html/json/csv/текст) |
| `parse_html` | Парс HTML | Извлечение | in | out:any | `selector` (line, CSS), `attr` (combo: текст/href/src) |
| `extract` | Извлечь данные | Извлечение | in | out:any | `mode` (combo: regex/json-ключ/числа/ссылки), `pattern` (line) |
| `clean` | Очистить | Извлечение | in | out:any | `what` (combo: пробелы по краям/дубли/пустые) |
| `loop` | Для каждого | Логика | in | out:any | `step` (line: подпись шага) |
| `act_use` | Использовать у себя | Действия | in | — (0 выходов) | `where` (combo: в описание/в заметку/в переменную), `name` (line) |
| `act_export` | Экспорт отчёта | Действия | in | — | `fmt` (combo: markdown/json) |

Категории и цвета точек — SPEC_UI п. 2.

## 9. `unknown` — защита от битых схем

Если при загрузке встречен узел с неизвестным `type` (удалили блок в новой версии, битый JSON), узел **не удаляется**: в реестре есть спецификация `unknown` (название «Неизвестный узел», без портов, полоса `BORDER_SUBTLE`), он рисуется приглушённо, и в тултипе — «этот тип узла не распознан». Пользователь удаляет его сам; так мы не теряем его данные молча.

## 10. Правила целостности (`core/validation.py`)

- `can_connect(schema, from_node, from_port, to_node, to_port) -> str | None`. Возвращает `None` (можно) или причину отказа:
  1. узел-источник и узел-приёмник совпадают → «нельзя соединить узел с самим собой»;
  2. создание связи образует цикл (от `to_node` по направлению рёбер достижим `from_node`) → «цикл в схеме»;
  3. узел-источник не имеет такого выхода / узел-приёмник не имеет такого входа → ошибка интерфейсная (обычно после поломки схемы).
- Вход занять можно всегда: старая связь на этот вход **удаляется** (правило одна связь) — пользователь тем самым переподключает.
- Проверки при загрузке: дубли id узлов/связей → оставить первый экземпляр, остальные отбросить (с предупреждением в тосте); связь на несуществующий узел/порт → удалить связь; «висячих» связей к unknown-узлам не создаём — unknown без портов.
